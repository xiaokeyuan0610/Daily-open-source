# 每日开源推荐 · Daily Open Source Picks

## 热门五项与通俗详解（当前规则）

热门栏目扩展为最多5项：保留10个实用精选，额外按GitHub Trending日榜原顺序，从前15项中选取通过核验且不重复的项目，保留实际榜单名次。不是全网前五；不足五项时不凑数。

每个热门项目在群卡片与完整日报均展示“这是什么、适合谁、举个例子、工作流程”。说明区分独立软件与开发框架，解释必要术语；示例是用于理解的假设场景，不冒充亲测。安装、费用与注意事项在完整日报中保留。未知信息明确待核实。

热榜内容版本2、消息版本6。今日升级会重新采集热榜并补发一版，允许今日已入选的热榜项目保留并扩写，仍排除之前日期的推荐及今日实用精选。

## 今日热门（新增栏目）

保留10个实用精选，额外从 GitHub Trending 日榜前15项中，按榜单顺序选取最多3个通过许可证与维护核验、且未在历史或当天推荐中出现的项目。每项记录原榜单名次、页面公布的今日新增Star（缺失时明确标注），附中文场景、工作流程、完整核验来源。热榜数据是采集时的页面快照，不是北京时间零点至今的精确统计，不代表全网排名。

热榜抓取或中文生成失败时明确显示栏目暂不可用，仍发送10个实用精选；不回退成累计Star榜。历史中保存来源、采集时间、热榜项目，纳入长期去重。版本5首次上线会复用今天的实用精选，并补发一版含热榜的新卡片。外部定时服务按用户设置的北京时间9:30触发，GitHub原定时与补偿检查继续作为备用。

## 工作流程展示（当前版本）

群卡片和完整日报已用“工作流程”替换上手标签。每项展示一条具体工作的三步链：准备的素材或问题 → 工具支持的关键操作 → 得到的成果。流程根据项目 README 编写，每步最多24字；资料不明时标注待核实，不把安装部署步骤当成工作流程。安装方式和部署要求仍保留在完整日报中。

编辑版本为2、消息格式版本为4；旧的上手标签方案已被此方案替代。首次升级复用今日十个项目并补全工作流程，发送一版新卡片，后续同版本不重复推送。

## 今日首选与筛选规则

每天恰好一个“今日首选”，依据实用性、上手门槛与资料完整度由 AI 选择并解释推荐理由，不表示人工亲测或权威排名。其余九项继续按需求分组；每项展示具体使用场景和上手标签：下载安装、需要配置、自建服务、待核实。Docker 部署也归为自建服务。

每项按主要用途选择一个固定分类：文件管理、截图识别、任务管理、笔记写作、影音阅读、备份同步、办公处理、系统工具、设计创作、开发辅助。每类最多两个，程序校验不通过就停止，不能通过编造分类凑数。顶部需求导航可以将多个分类合并展示，合并后的导航组不受两项上限限制。

候选按搜索主题交错核验，避免总是先拿到大量同类项目。已有当日日报首次升级时，会读取原十个项目的 README 并重新编辑描述与分类，保留核验事实和去重记录，不替换项目。版本 3 新版卡片补发一次，之后同版本不重复发送。

## 阅读新版日报

飞书使用分类消息卡片：顶部显示分类与数量，项目按需求分组，每项展示短名称、简短用途和平台；点击项目名可进入仓库，顶部按钮打开完整日报。完整日报增加需求导航图，同时保留文字链接，便于在不支持图形的阅读器中查看。费用、许可证、维护日期、安装说明和注意事项继续保留在完整日报。

从旧版纯文本升级时，当日日报会复用已核验的原项目，补发一次新版卡片，并保存 `delivery_format_version: 2`；同版本再次运行不会重复发送。发送状态不确定时仍须人工核对，不自动重发。代码或任务配置更新会触发验证运行；历史归档提交不会触发。

AI 密钥优先读取 `AI_API_KEY`，兼容已有的 `DAILYOPEN` Secret。

每天北京时间 10:00，通过 GitHub API 核验实用开源软件，调用 AI 生成 10 项中文精选，归档日报并发到飞书群。

## 首次部署

1. 在 GitHub 新建公开仓库 `xiaokeyuan0610/daily-open-source`，默认分支使用 `main`。
2. 把本目录全部文件上传到仓库，包含 `.github/workflows/daily.yml` 和 `.gitignore`。不要上传真实密钥。
3. 在仓库 Settings → Secrets and variables → Actions → New repository secret 添加：

| Secret | 内容 |
| --- | --- |
| `AI_API_KEY` | MetaRouters 的 API Key，必填 |
| `FEISHU_WEBHOOK_URL` | 飞书群自定义机器人完整 Webhook，必填 |
| `FEISHU_SIGN_SECRET` | 机器人开启签名校验时填写 |

`GITHUB_TOKEN` 由 Actions 自动提供，无需手工创建。代码预设 AI 地址 `https://api.metarouters.org/v1`、模型 `gpt-6-sol`，使用 OpenAI 风格 `/chat/completions` 接口；尚需真实凭据验证服务兼容性及模型可用性。

4. Settings → Actions → General 允许工作流写入仓库。分支保护规则也必须允许归档提交。
5. Actions → 每日实用开源精选 → Run workflow。首次执行会调用付费 AI 接口并向群发送真实日报。检查 reports 目录、群消息和 data/history.json。

## 筛选与去重

搜索十类实用项目，每类最多 20 个候选，逐项核验，最多向 AI 提供 35 个通过核验的项目。要求非归档、非 fork、许可证可被 GitHub 识别、默认分支过去 365 天有提交。许可证不明或候选不足 10 个时停止，不凑数。

许可证和日期由程序从 GitHub 数据注入，AI 无法覆盖；平台、费用、安装方式由 AI 参考 README 描述，无依据应标注待核实。开源许可证识别不等于法律审查或软件安全保证。仓库 README 属于不可信资料，作为数据提供给 AI，不作为执行指令。

历史按仓库全名大小写不敏感去重，已生成但未发送的项目也保留；同一天重复运行复用原日报。重命名仓库可能影响长期去重。

## 归档与发送恢复

先提交 reports/YYYY-MM-DD.md 与 data/history.json，再发送摘要。摘要包含十个项目与完整日报链接；详尽许可证、提交、正式发布和安装说明链接在归档中。

发送前先提交 `sending` 状态；成功后写入 `sent`。网络中断或进程终止可能导致发送结果未知：此时自动重试停止，请先检查群消息。确认未收到后，手动运行并勾选 confirm_resend。若已经收到，手动把当日状态改为 sent 即可。Webhook 无幂等保障，无法承诺网络异常时绝对不重复。

失败显示在 Actions 与 GitHub 通知中；建议在 GitHub 个人通知设置中订阅 Actions 失败邮件。发送失败不再依赖同一 Webhook 报警。归档提交失败时，工作流保留 30 天恢复附件；处理后再重试。

## 调度说明

`0 2 * * *` 是 UTC 02:00，即北京时间 10:00。GitHub 定时任务可能排队延迟，不保证整点到达；公开仓库长期无活动可能停用定时任务。每天成功的归档提交可保持仓库活动，连续失败则需人工检查。

## 定时可靠性与补发

GitHub schedule 是尽力调度，可能延迟数小时或漏触发。当前保留北京时间10:00主触发，并在10:13至18:43之间每小时13分、43分补偿检查；这些检查仍依赖GitHub，不保证准点。运行前先检查当日发送状态，已发送则跳过AI生成和推送。发送结果不确定时仍需人工核对，不盲目重发。

需要更稳定的时间触发时，应接入独立调度服务，通过HTTPS POST调用：`https://api.github.com/repos/xiaokeyuan0610/Daily-open-source/actions/workflows/daily.yml/dispatches`，请求体为 `{"ref":"main"}`，授权令牌存于调度服务的加密凭据中。仓库限定令牌只授权本仓库，Actions写权限。不要把令牌放进URL、仓库或日志。外部触发绕开schedule队列，但Actions运行资源仍可能排队。独立调度服务尚未配置。
